Astralia DDD Glossary

The 18 curriculum terms, in English, with a plain definition, a killer analogy, and a real example from the repository. Absent concepts are marked explicitly: no code is invented.

Vocabulary authority: CONTEXT.md. Layer contract: tests/architecture.test.ts.

Glossary — 18 terms
Term Plain definition + analogy Example in Astralia
Domain The problem space that matters to the business: what the application must understand, not the technology it is built with.

Analogy: a bakery's domain is flour, ovens, and recipes — not the color of the delivery van.

Authenticating users, capturing birth data, and calculating the natal chart. All under src/domain/.
Domain model The code-level map of the meaningful concepts and rules of the problem; deliberately simplified.

Analogy: a city map shows streets and landmarks, not every car and cable.

User.entity.ts, Email.vo.ts, BirthData.vo.ts, NatalChart.vo.ts, chart enums and ports under ports/.
Bounded context A boundary within which a model and its vocabulary are valid and have a single meaning; outside it the same word may mean something else.

Analogy: a border between countries — "ticket" means one thing on a bus and another at a football match.

Auth, Birth Data and Chart: three models in one repo, each with its own src/domain/<context>/. Note: CONTEXT.md declares "single bounded context for now"; the curriculum uses the three-context lens as a working map.
Context map The map of how contexts or external systems relate to each other, and where translation from one model to another happens.

Analogy: the customs desk at the border — each side keeps its own rules, and translation happens only at the crossing.

The three boxes (Auth, Birth Data, Chart) plus the Caelus translation seam around CaelusBirthConverter.ts.
Ubiquitous language The vocabulary shared between domain participants and code, used consistently in conversations, docs, and identifiers.

Analogy: a team dictionary that players and coaches both read, so "dough" never means two different things in one recipe.

BirthData, NatalChart, whole-sign, dst-ambiguous, toUT, SearchCities — anchored in CONTEXT.md.
Entity An object with stable identity that persists through time and through changes in its attributes.

Analogy: you are still you at age 5 and age 50, though every cell changed.

src/domain/auth/User.entity.ts — two instances with the same id represent the same person; equals() compares by id.
Value object An object defined by its values, not by identity; normally immutable and interchangeable.

Analogy: two $5 bills are the same $5 — swapping one for the other changes nothing.

Email.vo.ts, Password.vo.ts, BirthData.vo.ts, NatalChart.vo.ts and the other chart .vo.ts files.
Invariant A rule that must remain true at a consistency boundary, no matter what happens around it.

Analogy: a fridge's rule — the inside temperature stays below the danger zone.

Validations in BirthData.create() (date 1800-today, lat -90..90, east-positive longitude, IANA timezone), in Email.vo.ts, and in NatalChart.create() (≥10 planets, 12 houses). The PLACIDUS and TROPICAL enums constrain the model; Whole Sign is not representable today.
Aggregate A group of objects treated as a single consistency boundary: they change together, and the group protects its own rules.

Analogy: a checkout cart and its items — you do not reach in and change a price; the cart handles the whole group.

The persisted birth-data boundary is a candidate to analyze; the current map does not name an explicit BirthData aggregate.
Aggregate root The identity-bearing entry point that controls the aggregate; outside it, the interior cannot be changed directly.

Analogy: the castle gate — visitors enter only through it, not through the walls.

No aggregate root is demonstrated in the current map. BirthData.vo.ts is a Value Object by convention; evidence of identity, lifecycle and invariants would be needed to call it a root.
Repository An inner-layer, collection-like interface for loading and saving domain objects, hiding how and where they are stored.

Analogy: ask the librarian for a book by title — you never walk into the storage room.

IAuthRepository and IBirthDataRepository; DrizzleBirthDataRepository is the implementation.
Port A contract owned by the domain/application that declares a needed capability without saying how it is fulfilled.

Analogy: a USB-C socket — it accepts any device with the right plug shape, no matter the brand.

IAuthRepository, IBirthDataRepository, IBirthToUTConverter, IGeocoder, IChartCalculator — all under ports/.
Adapter An outer-layer implementation or translator that satisfies a port.

Analogy: the plug that makes one specific device fit the socket.

BetterAuthRepository, DrizzleBirthDataRepository, CaelusBirthConverter, OpenMeteoGeocodingAdapter, CaelusChartCalculator.
Use case / application service An application-level coordinator for one user goal: it orchestrates the flow using ports, without loose domain rules or infrastructure details.

Analogy: the waiter runs the order from table to kitchen and back; the chef decides the recipe.

SignIn, SaveBirthData, GetBirthData, DeleteBirthData, SearchCities, CalculateChart.
Dependency rule Code dependencies point toward policy and abstractions: outer layers depend on inner ones, never the reverse.

Analogy: the onion — the core does not know the skin exists.

Domain does not import infrastructure/pages/db; application does not import infrastructure/pages/db; infrastructure does not import application/pages — verified by tests/architecture.test.ts.
Anti-corruption layer / translator A boundary that prevents an external model from leaking into the domain, translating between two worlds.

Analogy: a translator at a summit keeps each side speaking its own language.

CaelusBirthConverter translates birth data/local time into UT/Caelus terms. Label it as a translation adapter; do not claim a full ACL without more evidence.
Domain event A record that something important already happened, so other parts of the system can react without being asked to watch. It is immutable and named in the past tense.

Analogy: a wedding invitation — guests learn the wedding happened and react on their own; the couple does not call everyone.

Not modeled yet. The closest primitive is WarningCode[] ('dst-ambiguous', 'whole-sign') returned by SaveBirthData — a "something happened" signal, not yet a full event.
Unit test / Integration test A unit test proves one rule in isolation with plain inputs; an integration test proves the plumbing between parts. Domain tests should be the majority of the suite.

Analogy: testing brakes on a bench (unit) versus driving through traffic (integration).

Bench: BirthData.vo.test.ts, NatalChart.vo.test.ts. Plumbing: DrizzleBirthDataRepository.test.ts. Layer police: tests/architecture.test.ts.
